# 이미지 시퀀스 웹 뷰어 설계

## 목표

컬러 프레임과 깊이 프레임을 함께 재생하고 탐색하는 정적 웹 뷰어를 만든다. 애플리케이션은 별도 빌드 과정이나 외부 웹 라이브러리 없이 로컬 HTTP 서버에서 실행되어야 한다.

## 범위

포함 범위는 다음과 같다.

- 루트의 `manifest.json` 읽기와 검증
- 컬러 및 깊이 캔버스 동시 표시
- 재생, 일시정지, 처음으로, 이전 프레임, 다음 프레임 제어
- 슬라이더 탐색과 0.5배, 1배, 2배 속도 선택
- 현재 프레임 인덱스와 경과 시간 표시
- 깊이 원본과 따뜻한 컬러맵 모드 전환
- 전체 이미지 선로딩과 진행률 표시
- manifest 및 프레임 로딩 오류 안내
- Python 표준 라이브러리만 사용하는 30프레임 더미 데이터 생성기
- 자동 검사와 실제 브라우저 검증

다음은 포함하지 않는다.

- 정적 웹 뷰어와 무관한 작업
- 네트워크 업로드, 파일 선택기, 편집, 주석, 반복 재생
- 서버 애플리케이션이나 데이터베이스
- 외부 JavaScript 및 CSS 라이브러리

## 접근법

브라우저 기본 기능과 ES 모듈을 사용한다. 화면 연결 코드와 독립적으로 검증할 수 있는 manifest, 선로딩, 재생 상태, 깊이 변환 로직을 작은 모듈로 나눈다. Node.js 내장 테스트 러너로 독립 로직을 검사하며 애플리케이션 실행에는 Node.js나 패키지 설치가 필요하지 않다.

단일 JavaScript 파일은 초기 파일 수가 적지만 상태와 화면 처리가 결합되어 테스트와 변경 추적이 어려워 제외한다. Worker 및 `createImageBitmap` 기반 처리는 대규모 시퀀스에서 유용하지만 이번 과제 규모에는 복잡성 대비 이득이 작아 제외한다.

## 파일 책임

- `index.html`: 두 캔버스, 상태 영역, 재생 컨트롤의 의미 구조
- `styles.css`: 반응형 2열 레이아웃, 로딩과 오류 상태, 컨트롤 표현
- `src/manifest.js`: manifest 가져오기, 스키마 검증, 이미지 URL 해석
- `src/preload.js`: 모든 컬러와 깊이 이미지 선로딩, 진행률과 실패 수집
- `src/player.js`: 프레임 위치, 재생 속도, 재생 시계, 끝 동작 관리
- `src/depth.js`: 회색조 픽셀을 가까울수록 따뜻한 색으로 변환
- `src/app.js`: DOM 이벤트 연결, 캔버스 렌더링, 사용자 상태 표시
- `scripts/generate_dummy_data.py`: PNG 프레임과 manifest 생성
- `tests/`: 브라우저와 무관한 로직 및 생성 데이터 검사

## manifest 계약

애플리케이션은 `./manifest.json`을 읽고 이미지 경로를 manifest URL 기준으로 해석한다. 다음 조건을 만족하지 않으면 로딩을 중단하고 오류를 표시한다.

- 최상위 값은 객체여야 한다.
- `frame_count`는 1 이상의 정수이며 `frames` 길이와 같아야 한다.
- `interval_ms`는 0보다 큰 유한 숫자여야 한다.
- `depth_near_cm`과 `depth_far_cm`은 유한 숫자이며 가까운 값이 먼 값보다 작아야 한다.
- 각 프레임의 `index`는 0부터 빠짐없이 증가해야 한다.
- `color`와 `depth`는 비어 있지 않은 문자열이어야 한다.
- `time_ms`는 0 이상의 유한 숫자이며 앞 프레임보다 작아지지 않아야 한다.

## 데이터 흐름

1. 페이지를 열면 모든 조작을 비활성화하고 manifest를 가져온다.
2. manifest를 검증하고 각 이미지 URL을 절대 URL로 정규화한다.
3. 컬러와 깊이 이미지 총 `frame_count × 2`개를 모두 선로딩한다.
4. 이미지 하나가 성공하거나 실패할 때마다 진행률을 갱신한다.
5. 하나라도 실패하면 실패 파일을 포함한 오류를 표시하고 조작을 비활성 상태로 둔다.
6. 모두 성공하면 첫 프레임을 두 캔버스에 그리고 조작을 활성화한다.
7. 사용자 입력과 재생 시계가 현재 프레임을 바꾸면 두 캔버스를 같은 인덱스로 다시 그린다.

## 재생 동작

`requestAnimationFrame`의 타임스탬프 차이를 누적하고 `interval_ms ÷ 재생 속도`마다 다음 프레임으로 이동한다. 일시정지 후 재개할 때 정지 시간은 누적하지 않는다. 마지막 프레임에 도달하면 일시정지한다. 마지막 프레임에서 재생을 누르면 0번 프레임으로 이동한 뒤 재생한다.

처음으로는 0번 프레임으로 이동하면서 재생을 멈춘다. 이전과 다음 이동도 재생을 멈춰 사용자가 선택한 프레임을 안정적으로 확인할 수 있게 한다. 슬라이더 탐색 역시 재생을 멈춘다.

프레임 표시는 manifest의 0 기반 `index`를 사용하며 경과 시간은 해당 프레임의 `time_ms`를 `분:초.밀리초` 형식으로 표시한다.

## 깊이 표시

원본 모드는 깊이 PNG를 그대로 그린다. 컬러맵 모드는 각 픽셀의 RGB 평균 밝기를 0부터 1 사이 값으로 정규화하고, 밝을수록 가까운 값으로 해석해 파랑, 청록, 노랑, 주황, 빨강 순서의 색으로 변환한다.

manifest에는 PNG 픽셀값과 실제 센티미터 사이의 인코딩 규칙이 없으므로 `depth_near_cm`과 `depth_far_cm`은 계약 검증에 사용하되 픽셀 변환식에는 직접 사용하지 않는다. 이 판단은 임의의 단위 변환으로 잘못된 깊이를 표현하지 않기 위함이다.

## 오류 처리

오류는 페이지 안의 `role="alert"` 영역에 한국어로 표시한다.

- HTTP 또는 JSON 파싱 실패: 로컬 서버 실행 여부와 `manifest.json` 위치 확인 안내
- manifest 계약 위반: 잘못된 필드와 기대 조건 안내
- 이미지 실패: 실패한 컬러 또는 깊이 파일 경로 안내
- 캔버스 처리 실패: 해당 프레임과 다시 생성할 데이터 안내

개발자 콘솔에는 원래 오류를 남기되 사용자 화면은 기술 스택을 몰라도 다음 행동을 이해할 수 있는 문장으로 구성한다.

## 화면과 접근성

넓은 화면에서는 컬러와 깊이를 같은 크기의 2열로 표시하고 좁은 화면에서는 세로로 쌓는다. 캔버스 내부 해상도는 원본 이미지 크기를 사용하고 CSS로 가용 너비에 맞춘다. 모든 조작은 실제 `button`, `input`, `select` 요소를 사용하며 연결된 레이블과 포커스 표시를 제공한다. 상태와 오류는 보조 기술에 전달되는 live 영역을 사용한다.

## 더미 데이터

Python의 `struct`, `zlib`, `binascii`, `json` 모듈로 PNG 청크를 직접 작성한다. 컬러 프레임에는 화면을 가로지르는 원과 배경 안내선이 있고 깊이 프레임에는 같은 원이 점점 밝아져 가까워지는 모습을 표현한다. 기본 실행은 저장소 루트에 30쌍의 PNG와 `manifest.json`을 만들며 생성 파일은 Git 추적에서 제외한다.

## 검증

- Node.js 내장 테스트로 manifest 검증, URL 해석, 진행률, 실패 수집, 재생 경계, 속도, 깊이 색상 변환을 검사한다.
- Python 내장 `unittest`로 PNG 서명, 크기, 파일 수, manifest 일관성을 검사한다.
- `python -m http.server`로 실제 정적 서버를 띄운다.
- 통합 브라우저에서 로딩 완료, 두 캔버스, 재생과 일시정지, 처음으로, 앞뒤 이동, 슬라이더, 세 속도, 깊이 모드, 오류 표시를 확인한다.
- 데스크톱과 모바일 너비에서 겹침과 잘림을 확인하고 브라우저 콘솔 오류를 점검한다.

## 버전 관리

main에는 초기 저장소 뼈대만 유지한다. 모든 설계, 구현, 테스트, 문서 변경은 `stage/01-web-viewer`에서 기능 단위 한글 커밋으로 기록하고 원격 브랜치에 푸시한다. 리뷰 전에는 main에 병합하지 않는다.
